# newsletters

**VISIWING Weekly · Research & Newsletter Engine**

**Independent repository – Gemini Deep Research-first.** Researches SEO/GEO/AI Search, evaluates tools and experiments, and prepares source-cited editorial newsletter **drafts**. Does not silently send marketing email.

## Architecture

```text
Weekly trigger (GitHub Actions/manual)
     |
     v
Previous newsletter memory + editorial brief + optional RSS leads
     |
     v
Gemini Deep Research MAX (Interactions API, long-running, resumable)
     |
     v
Full cited research report (archived locally; no fabricated fallback)
     |
     v
Gemini editorial pass -> validated cited structured JSON
     |
     v
newsletter.md + newsletter.html + newsletter.json
     |
     v
GitHub PR -> manual editorial review -> publishing integration (future)
```

RSS feeds are **optional lead generation**, not the core research. Gemini autonomously searches and cross-checks the open web, asks what changed, and evaluates primary evidence.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m intelligence.cli demo             # Real publicly sourced editorial SAMPLE, no API charge
python -m intelligence.cli weekly --dry-run # Inspect research plan; no API charge
export GEMINI_API_KEY='YOUR_KEY'            # or use secure env / GitHub secret
python -m intelligence.cli weekly --agent max
```

Find output under `out/YYYY-MM-DD/`: HTML, Markdown, JSON. Open HTML in a browser. `weekly --agent standard` selects cheaper standard Deep Research.

The `demo` example (October 14, 2026) is **not** generated by Gemini. It is a curated demonstration referencing public first-party publications. Actual Gemini execution requires a valid billed API key; no simulated Gemini report is supplied on failure.

## GitHub setup

This project lives separately from SEOGEO8. An existing GitHub repository currently resolves to `os110787/newsletters-` (with a trailing hyphen); this differs from the short project name `newsletters`. To push this standalone project to that repository:

```bash
# From inside the extracted project folder:
git init -b main
 git add . && git commit -m 'Initial standalone Gemini Deep Research intelligence engine'
 git remote add origin https://github.com/os110787/newsletters-.git
 git push -u origin main
```

Add `GEMINI_API_KEY` under **GitHub repository → Settings → Secrets and variables → Actions**. Enable Actions and grant `GITHUB_TOKEN` write permissions / allow Actions-created PRs. A scheduled weekly job on Thursdays (05:15 UTC) creates a **review PR only**, never sends emails. Check model availability and budget in your Google project before enabling cron. GitHub Actions schedules can run late or be skipped; use an external scheduler for strict SLAs.

## Safety and editorial quality

- No marketing delivery without consent, double opt-in, unsubscribe flow, and human approval.
- Research uses official Gemini Interactions API with `background=True`, polls completion, stores task ID to resume without duplicate charging.
- Calls default to **one Max research task weekly**, not per topic; optional RSS discovery is cheap.
- Dates are part of the research prompt; exact event date and publishing date should be editorially reviewed.
- Editorial JSON can only use URLs already present in the Deep Research report; this limits invented links but **is not independent verification**.
- Failure to obtain a cited report or structured editorial output **fails closed**.
- Every newsletter item starts `review_status=pending`.
- Prior report text is untrusted context; research/news are *data*, not instructions.
- Sources & claims require review for copyright, conflicting evidence, misleading causal claims, and commercial relevance.
- `out/` and local SQLite are data artifacts, not credentials; interaction metadata and raw reports are intentionally gitignored.

## Configuration

- `GEMINI_API_KEY` required for real research and editorial generation.
- `GEMINI_EDITOR_MODEL` defaults to `gemini-2.5-flash`, configurable.
- `config/sources.json` optional 10 RSS/RDF feeds; run `python -m intelligence.cli ingest` to populate optional research hints.
- `research.py`: category prompt, date window, research-history exclusion, and agent selection.
- `editorial.py`: extraction, source URL validation, newsletter rendering.
- `examples/sample-issue-2026-10-14.json`: real first-party source examples; no API claim.

## Cost guardrails

Google's documentation estimates roughly **USD 3–7** for a representative Deep Research Max task and **USD 1–3** for standard, but actual usage depends on the research workload, search tools, tokens and pricing tier. The editorial model adds cost. Limit scheduled tasks and configure billing alerts/quotas in your Google project. This package does not implement a hard API spending ceiling.
